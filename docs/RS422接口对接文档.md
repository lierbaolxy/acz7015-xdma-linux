# RS422接口对接文档

> 本文档供上位机同事对接RS422数据使用，包含硬件连接、数据格式、运行步骤。

## 一、系统架构

```
轨迹球(被测设备) ──RS422──> TTL转RS422隔离模块 ──TTL──> ACZ7015 40pin排针
                                                              │
                                                    PS UART1(EMIO)
                                                              │
                                              写入DDR共享内存 0x20000060
                                                              │
                                          PC端通过XDMA读取DDR数据
```

## 二、硬件连接

### 2.1 TTL转RS422模块参数
- **型号**：TTL转RS422全双工隔离型模块（3.3V供电）
- **工作电压**：3.3V（与ACZ7015 PL侧LVCMOS33电平兼容）
- **隔离**：光耦隔离，防止外部信号反灌损坏FPGA
- **接口**：全双工（TX/RX/GND）

### 2.2 接线方式

| ACZ7015 40pin排针 | 物理引脚 | FPGA引脚 | 功能 | TTL模块引脚 |
|-------------------|----------|----------|------|-------------|
| pin26 | E5 | UART1_TX_O | 数据发送 | RX（交叉连接） |
| pin28 | B1 | UART1_RX_I | 数据接收 | TX（交叉连接） |
| pin11 | - | - | 3.3V电源 | VCC |
| pin12 | - | - | GND | GND |

**重要**：
- TX/RX必须交叉连接（ACZ7015的TX接TTL模块的RX）
- 必须共地（GND相连）
- 3.3V供电由ACZ7015排针pin11提供

### 2.3 硬件安全性验证结论
- **电压兼容**：TTL模块3.3V与FPGA LVCMOS33完全兼容，无烧板风险
- **引脚分配**：E5/B1已通过Vivado约束文件确认，无引脚冲突
- **隔离保护**：隔离型模块能防止外部信号反灌损坏FPGA
- **结论**：可以安全上电测试

## 三、数据格式

### 3.1 DDR共享内存布局

| 接口 | 槽位地址 | device_id | 说明 |
|------|----------|-----------|------|
| USB | 0x20000000 | 0 | USB鼠标数据 |
| CAN | 0x20000020 | 1 | CAN数据（预留） |
| PS2 | 0x20000040 | 2 | PS2数据（预留） |
| **RS422** | **0x20000060** | **3** | **RS422数据** |

### 3.2 槽位结构（32字节，对齐cache line）

```c
typedef struct {
    uint32_t seq;        // 0x00: 序号，每次事件+1（PC端检测变化）
    uint32_t device_id;  // 0x04: 接口类型，RS422=3
    uint32_t data_len;   // 0x08: 有效数据长度（不含data[0]标识字节）
    uint32_t reserved;   // 0x0C: 保留对齐
    uint8_t  data[8];    // 0x10: data[0]=报文标识, data[1..]=有效数据
    uint32_t tv_sec;     // 0x18: 开发板时间戳-秒
    uint32_t tv_nsec;    // 0x1C: 开发板时间戳-纳秒
} share_slot_t;  // 共32字节
```

### 3.3 data[8]字段封装

| 字节 | 内容 | 说明 |
|------|------|------|
| data[0] | 报文标识 | 0xD1-0xD5，见下表 |
| data[1..data_len] | 有效数据 | 长度由报文类型决定 |
| data[1+data_len..7] | 0x00 | 剩余字节清零 |

### 3.4 RS422报文类型

| 报文名称 | 标识(data[0]) | 有效数据长度 | data_len字段值 |
|----------|---------------|-------------|----------------|
| 位移信息 | 0xD1 | 3字节 | 3 |
| 状态信息 | 0xD2 | 3字节 | 3 |
| BIT温度 | 0xD3 | 1字节 | 1 |
| BIT电压 | 0xD4 | 2字节 | 2 |
| 软件版本 | 0xD5 | 3字节 | 3 |

### 3.5 各报文数据格式

#### 位移信息（0xD1，data[1..3]）
| 字节 | 内容 |
|------|------|
| data[1] | bit0=左键, bit1=右键, bit4=X符号, bit5=Y符号 |
| data[2] | X位移（int8补码） |
| data[3] | Y位移（int8补码） |

#### 状态信息（0xD2，data[1..3]）
| 字节 | 内容 |
|------|------|
| data[1] | bit6=模式(1=Remote,0=Stream) |
| data[2] | 分辨率 |
| data[3] | 采样率 |

#### BIT温度（0xD3，data[1]）
- signed char，单位℃（如0x25=37℃）

#### BIT电压（0xD4，data[1..2]）
- 低8位在前，高8位在后，单位10mV
- 如 data[1]=0x40, data[2]=0x01 → 0x0140 = 320 → 3.2V

#### 软件版本（0xD5，data[1..3]）
- 如 data[1]=0x02, data[2]=0x00, data[3]=0x01 → 版本2.01

## 四、XDMA读写操作

### 4.1 设备节点
- **读取设备**：`\\?\pci#ven_10ee...#{GUID}\c2h_0`（Card-to-Host，DMA读）
- **GUID**：{74c7e4a9-6d5d-4a70-bc0d-20691dff9e9d}

### 4.2 读取流程（C++示例）

```cpp
#include <windows.h>
#include <setupapi.h>
#pragma comment(lib, "setupapi.lib")

// 1. 通过SetupAPI枚举设备获取路径
// 2. CreateFileA打开c2h_0设备（需要GENERIC_READ|GENERIC_WRITE权限）
HANDLE h = CreateFileA(devicePath, GENERIC_READ|GENERIC_WRITE,
                       0, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);

// 3. SetFilePointerEx设置DDR地址（RS422槽位=0x20000060）
LARGE_INTEGER offset;
offset.QuadPart = 0x20000060;
SetFilePointerEx(h, offset, NULL, FILE_BEGIN);

// 4. ReadFile读取64字节（XDMA驱动要求读64字节，即使槽位只有32字节）
BYTE buf[64];
DWORD got = 0;
ReadFile(h, buf, 64, &got, NULL);

// 5. 解析前32字节为share_slot_t结构
// 6. 检测seq变化：seq != last_seq 表示有新数据
```

### 4.3 关键注意事项
1. **必须使用同步I/O**：`FILE_ATTRIBUTE_NORMAL`，不要用`FILE_FLAG_OVERLAPPED`
2. **必须读64字节**：XDMA驱动要求，即使只需要32字节
3. **必须有GENERIC_WRITE权限**：仅GENERIC_READ会导致读取失败
4. **正常退出**：用Ctrl+C退出，不要强杀进程（会导致DMA引擎卡死）

## 五、运行步骤

### 5.1 前置条件
1. SD卡已烧录包含UART1 EMIO配置的bitstream（SYSTEM_xdma.bit）
2. 设备树已启用UART1（serial@e0001000 status=okay）
3. TTL转RS422模块已正确连接到40pin排针

### 5.2 PS端（开发板）运行

```bash
# 1. 停止串口控制台服务（释放ttyPS0给RS422使用）
sudo systemctl stop serial-getty@ttyPS0.service

# 2. 编译
cd /path/to/latency_test
gcc -O2 -o arm_rs422_sender arm_rs422_sender.c

# 3. 运行（默认使用/dev/ttyPS0，即UART1）
sudo ./arm_rs422_sender
# 或指定设备
sudo ./arm_rs422_sender /dev/ttyPS0
```

**输出示例**：

### 5.4 启动顺序
**建议先启动PS端，再启动PC端**：
1. PS端先启动，开始监听串口并写入DDR
2. PC端后启动，读取DDR中的数据

如果顺序反了，PC端会显示"等待数据..."直到PS端开始写入。

### 5.5 退出方式
- **PS端**：按Ctrl+C正常退出
- **PC端**：按Ctrl+C正常退出（会自动关闭XDMA设备句柄）

**禁止使用任务管理器强杀进程**，会导致XDMA DMA引擎卡死，需要重启电脑恢复。

## 六、协议帧格式（原始RS422）

### 6.1 帧结构
```
帧头(0x55) | 报文标识 | 有效数据 | 校验和
```

### 6.2 校验和计算
- 范围：从帧头开始到有效数据最后一字节
- 算法：所有字节累加取低8位

**示例**（位移信息报文，X=10, Y=-5, 无按键）：
```
帧头:    0x55
标识:    0xD1
data[0]: 0x10  (bit4=1表示X为正... 实际bit4是X符号位,1=负向)
data[1]: 0x0A  (X=10)
data[2]: 0xFB  (Y=-5的补码)
校验和:  0x55+0xD1+0x10+0x0A+0xFB = 0x1EB & 0xFF = 0xEB
完整帧:  55 D1 10 0A FB EB
```

## 七、故障排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| PS端"打开串口失败" | serial-getty占用 | `sudo systemctl stop serial-getty@ttyPS0.service` |
| PS端无数据输出 | TTL模块接线错误 | 检查TX/RX交叉连接 |
| PC端"未找到XDMA设备" | XDMA驱动未安装 | 检查设备管理器，安装驱动 |
| PC端"打开设备失败" | XDMA设备被占用 | 关闭其他XDMA程序 |
| PC端收到数据但解析错误 | 字节序/符号位错误 | 检查data_len判断条件 |
| PC端无数据输出 | 启动顺序错误 | 先启动PS端再启动PC端 |
| 数据延时过大 | 轮询间隔 | 检查time.sleep设置 |

## 八、风险提示

1. **bitstream要求**：必须使用包含UART1 EMIO配置的bitstream（引脚E5=TX, B1=RX）
2. **串口占用**：UART1默认被console占用，运行前必须停止serial-getty服务
3. **电压兼容**：TTL模块必须使用3.3V版本，5V版本会损坏FPGA
4. **共地**：TTL模块和开发板必须共地，否则通信不稳定
5. **正常退出**：PC端必须用Ctrl+C退出，强杀进程会导致XDMA卡死
